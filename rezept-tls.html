TLS 1.3 (HTTPS)

Das Drei-Gänge-Menü, das du jeden Tag isst, ohne es zu merken.

Definition

Transport Layer Security sichert die Verbindung zwischen Browser und Webserver. TLS ist kein einzelnes Verfahren, sondern ein ganzes Menü: Diffie-Hellman liefert den gemeinsamen Schlüssel, Zertifikate und Signaturen beweisen die Echtheit des Servers, und AES-GCM schützt die Daten vor Mitlesen und Verändern.

Zutaten

  • ECDH-Schlüsselaustausch (z. B. X25519)
  • Server-Zertifikat von einer vertrauenswürdigen CA
  • Digitale Signatur
  • HKDF zur Schlüsselableitung
  • AES-GCM oder ChaCha20-Poly1305

Zubereitung

  1. ClientHello: Der Browser schickt unterstützte Verfahren, eine Zufallszahl und seinen Diffie-Hellman-Anteil (Key Share).
  2. ServerHello: Der Server wählt die Verfahren und schickt seinen eigenen Key Share.
  3. Beide berechnen das gemeinsame Geheimnis und leiten daraus mit HKDF die Sitzungsschlüssel ab. Ab jetzt ist alles verschlüsselt.
  4. Der Server schickt sein Zertifikat und signiert den bisherigen Handshake (CertificateVerify).
  5. Der Browser prüft Zertifikatskette, Domainnamen und Signatur.
  6. Beide schicken eine Finished-Nachricht mit einem MAC über den ganzen Handshake.
  7. Die eigentlichen HTTP-Daten fließen mit AES-GCM geschützt.

Tipps

  • Auf Servern nur TLS 1.2 und 1.3 erlauben, ältere Versionen sind unsicher.
  • Das Schloss bedeutet nur, dass die Verbindung zu dieser Domain sicher ist – nicht, dass die Seite vertrauenswürdig ist. Auch Phishing-Seiten haben ein Schloss.
  • Zertifikate gibt es kostenlos bei Let's Encrypt.
  • Mit HSTS sagt ein Server dem Browser, dass er nur noch per HTTPS besucht werden will.
  • Die eigene Server-Konfiguration lässt sich mit dem SSL Server Test von Qualys SSL Labs prüfen.
